### Known limitations (honest status)

- No VeNCrypt/TLS, ARD/Apple auth. Tight/Hextile not implemented; Raw/CopyRect/ZRLE decode correctly (ZRLE added 2026-11-19). Remote plain RFB is blocked off-loopback unless the profile explicitly opts into `legacy`.
- Clipboard sync (text, both directions) is implemented; key mapping is egui-level (no native NSEvent IME handling); scroll sent as button 4–7 pulses; full-frame RGBA upload only at first frame / resize (partial uploads elsewhere).
- Handshake phase has no read timeout (steady-state streaming must not time out, so a stalled server shows "Connecting…" until the user backs out).
- Pointer releases that occur completely outside any GlintVNC window (multi-monitor, pointer on another display) cannot be captured (macOS has no OS pointer grab for this app); the cursor re-entering the window restores sync on the next motion/press/release. Focus loss/disconnect still releases everything via `release_held`.
- Signed only ad-hoc: Keychain ACL may re-prompt after rebuilds; Developer ID + notarization required for distribution.
- No app icon is included in the design system sense — a procedural placeholder icon (`assets/GlintVNC.icns`, generated by `scripts/make-icon.py`) ships in the bundle; AI-generated art was unavailable (provider credential error) and may be replaced.
- Username for the LAN server is unused (classic VNC auth has no username field); if the server requires ARD-style user+password, this client cannot authenticate yet.
- Tests used Python mock at 127.0.0.1:5999 and the user-authorized LAN server only after explicit user consent.
